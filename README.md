# サークル（試作）

名前の「サークル」は、使う人が引っかかる角（分かりにくい言葉、読めない文字、届かない知らせ）をできるだけ減らして、丸に近づけていくことを理想にしているからです。

いまいる場所について、公式に出ている防災の情報を集めて並べる試作です。
大雨・土砂災害・高潮・氾濫のレベル３以上が出ていると、その場所の性質（ハザードマップの区域など）とあわせて通知します。
ツキノワグマの出没の記録が地点から 1km 以内・60 日以内にあるときも、通知します（いまは秋田県の公開データの分）。
通知の題は「新宿区 レベル3 氾濫警報」のように、どこで何が出ているかを先に書きます（たたんだ通知で切れない 16 字ほど。絵文字は使いません）。たたんだ 2 行目は題をくり返さず、ひらがなと英語の決まった訳です。
本文は、出どころといつ（気象庁と発表時刻）、気象庁の警報の文の形の案内 1 文（警報は「初台アンダーの冠水に警戒してください」、注意報は「〜に注意してください」。この場所のものを名指しする）、そしてこの場所の公式の事実と出典へのリンクです。逃げる・避難など、どう逃げるかは書きません。

## 動かし方

Python 3 の標準ライブラリだけで動きます。

```
cd app
python3 app.py
```

ブラウザで http://127.0.0.1:8765/ を開き、「現在地で調べる」を押します。
URL に `?lat=34.47&lon=132.47` を付けると、その地点で調べます。
`python3 app.py --point 34.47,132.47` は、結果を JSON で出します。
テストは `python3 -m unittest test_app test_compose test_phone` です。

### 試し（作りものの警報）

警報が出ていないときでも、知らせと通知を見られます。
画面の「試し」で作りものの警報を 1 つ選ぶと、それを足して調べ直します。ほかの情報はいまの本物です。
URL なら `?lat=35.7106&lon=139.8133&demo=flood:4`、JSON なら `python3 app.py --point 35.7106,139.8133 --demo flood:4` です。
`demo` は `rain`（大雨）・`landslide`（土砂災害）・`flood`（氾濫）・`tide`（高潮）と、`:2`～`:5` のレベルです。
作りものの警報は、名前・知らせの題・本文のすべてに「試し」と書きます（題は「試し ⛰️ 土砂災害に気をつけて」）。

## 携帯に通知する

携帯のアプリ（`phone/`）が自分の位置を Firebase に書き、PC の `app/phone.py` がそれを読みに行って調べます。
知らせることがあると、PC が Firebase Cloud Messaging の優先度の高い push で携帯に送ります。
携帯を置いたままでも push で起きるので、知らせが遅れません。PC は読みに行くだけで、外からの接続は受けません。
通知の題は「⛰️ 土砂災害に気をつけて」の形です。たたんだ通知は 15 字ほどで切れるので（エミュレータで確かめました）、題は切れない長さにします。レベルの数字を題の後ろに置くと「レベ…」で切れたので、レベルは、たたんだ通知の 2 行目（「千代田区にレベル４土砂災害危険警報」）と色（警戒レベルの色）で出します。
本文は、まず公式の事実（警報の正式な名前、その場所の区域・危険度・雨など）と、そのよみがな・公式の英語、そのあとにボタンにないページの名前です。
通知の文字はリンクにならないので、はじめの 2 つのページ（例: 「警報（気象庁）」「土砂災害の地図」）は通知のボタンで開きます。同じ名前を本文にもう一度は書きません。通知を押すとアプリが開き、最後に届いた知らせ（題・届いた時刻・公式のページの一覧）と、位置を送れているか（送れないときは設定を開く「直す」）が出ます。

位置を読めるのは PC のサービスアカウントだけです（`firestore.rules` で携帯からも誰からも読めません）。
位置は PC の画面にも記録にも出しません。

### 用意（最初の 1 回）

1. Firebase コンソールで新しいプロジェクトを作ります。料金プランは Spark（無料）のままにします。Google アナリティクスは要りません。
2. Android アプリを追加します。パッケージ名は `io.github.jawsy.imakoko` です。`google-services.json` をダウンロードして PC に置きます（このリポジトリには入れません）。
3. Firestore Database を作ります。本番環境モード、場所は `asia-northeast1`（東京）です。「ルール」に `firestore.rules` の中身を貼って公開します。
4. プロジェクトの設定 → サービス アカウント → 新しい秘密鍵を生成します。できた JSON を PC に置き、`chmod 600` にします（このリポジトリには入れません）。
5. PC で携帯を 1 台つなぎます。出てきた 1 行（設定の文）を携帯に送ります。

```
cd app
python3 phone.py pair --google-services ~/firebase/google-services.json --name phone
```

6. 携帯にアプリを入れて開き、「設定」に設定の文を貼って「設定を保存」、「位置を送り始める」を押します。
   通知・位置・位置の「常に許可」を順に聞かれます。

### 試す・動かす

```
python3 phone.py test --key ~/firebase/service-account.json            # 作りものの警報（土砂災害 4）で、いま 1 回送る
python3 phone.py test --key ~/firebase/service-account.json --demo flood:3
python3 phone.py watch --key ~/firebase/service-account.json           # 3 分ごとに調べ、新しい知らせだけ送る
```

`watch` は、警報が新しく出た・レベルが上がった・場所の区域が変わった・クマの新しい記録が載ったときだけ送ります。同じ警報の出し直しでは送りません。
携帯から 2 時間より長く位置が届いていないときは、知らせにそのことを書きます。
テストは `python3 -m unittest test_phone test_app test_compose` です。

### 携帯アプリを組む

JDK 17 と Android SDK（platform 35、build-tools 35.0.0）が要ります。

```
cd phone
./gradlew testDebugUnitTest assembleDebug
```

できた APK は `phone/app/build/outputs/apk/debug/app-debug.apk` です。

## Claude で知らせの文を組み立てる

知らせの文は、PC で Claude API のキーを設定したときだけ Claude が組み立てます。設定しなければ、公式の事実を並べた文のままです。

```
pip install -U anthropic
export ANTHROPIC_API_KEY=...      # 環境変数だけに置きます。ファイルやこのリポジトリには書きません
python3 app.py
```

- Claude に渡すのは、知らせに入れる公式の事実の文と id だけです。位置・出典・URL は渡しません。
- Claude は事実をつないで読みやすい文にし、文ごとにどの事実を使ったかを返します（JSON の形を決めて受け取ります）。
- アプリが 1 文ずつ確かめます。
  - 事実をすべて使っているか。
  - 事実にない数字・数字の幅・漢数字の数・「」や（）の中の名前が無いか。
  - どう動くか（避難・ください など）、安全・心配ない、予想・おそれ を書いていないか。事実の文にもともとある言葉は使えます。
  - 試しの事実の文は、それだけで最初の 1 文にし、「試し」と書いているか。試しの印はその 1 か所だけです。
- 案内の 1 文（「〜に警戒してください」）は Claude に渡しません。アプリの文のまま、2 文目に入れます。
- 1 つでも外れたら Claude の文は使わず、事実を並べた文に戻します。画面には戻した理由を出します。
- 出典は Claude に書かせず、文ごとに使った事実の出典をアプリが付け直します。
- 同じ事実の知らせには 1 回だけ問い合わせ、返事を覚えておきます。モデルは `claude-opus-5-5` で、混んでいるときは API 側の代わりのモデルに回ります。
- 画面は、まず事実を並べた文を出し、Claude の文が確かめ終わったら差し替えます。携帯の通知はページの名前だけなので、Claude は使いません。
- 使わないときは `app.py --no-claude` か `IMAKOKO_CLAUDE=off` です。モデルは `IMAKOKO_CLAUDE_MODEL` で変えられます。

## 知らせの作り

通知の題・たたんだ 1 行・本文は、警報の文や通知の作りについての調べものにそって作りました。
- 本文の並びは、出どころ → 何の危険 → どこ → いつ → 何に気をつけるか。この 5 つがそろった警報の文ほど分かりやすい、という研究にそいました（[START/UMD](https://www.start.umd.edu/news/study-shows-longer-emergency-text-alerts-improve-safety)、[Sutton & Cain](https://hazards.colorado.edu/uploads/poster_session/Sutton_Cain_2024NHWPoster.pdf)）。
- 題は 16 字ほどで、どこで何が出ているかを先に書きます。たたんだ通知で切れないためです（[Android の通知](https://developer.android.com/design/ui/mobile/guides/home-screen/notifications)、緊急速報メールの題も 15 字: [消防庁](https://www.fdma.go.jp/laws/tutatsu/assets/290131_jimurenraku.pdf)）。たたんだ 2 行目は題をくり返しません。
- やさしい日本語の行は短く、同じことを何度も書きません（[やさしい日本語ガイドライン](https://www.moj.go.jp/isa/support/portal/plainjapanese_guideline.html)）。
- 🌊 は使いません。図記号では洪水と津波は別の絵で、絵文字は機種で絵が変わります（[内閣府 図記号](https://www.bousai.go.jp/kyoiku/zukigo/index.html)）。レベルは数字の文字で書きます。
- 試しの印は 1 か所だけにし、本物の行を名指しします。全国一斉の試しでも「TEST」に迷う人が出ています（[The Conversation](https://theconversation.com/nationwide-test-of-wireless-emergency-alert-system-could-test-peoples-patience-or-help-rebuild-public-trust-in-the-system-214453)）。
- 案内の 1 文は気象庁の警報の文の形です。注意報は「〜に注意してください」、警報から上は「〜に警戒してください」で、この場所のもの（道の名前など）を名指しします。

## 作りものの人で角を数える

角は、作りものの人（実在の人ではない）100 人に、携帯の画面の写し 4 枚を見てもらって数えます。
人は、年齢・読める文字（漢字まで、ひらがなまで、日本語はほとんど読めない）・目や耳の様子・その場所にいるわけが、一人ずつちがいます。
Claude がその人を演じ、写しに見えるものだけから、何が分かったかと、どこが角かを答えます。写しはエミュレータで撮ったものです（`persona/look/shots/`）。

```
cd persona
python3 look.py run --set after3 --round look-after3 -j 4   # 1 人に 1 回 claude -p。道具・MCP・設定は使わない
python3 look.py tally look-before look-after look-after2 look-after3   # 表を runs/look-after3/tally.md に書く
```

| | 直す前 | 見た目を直した後 | 2 つを直した後 | 作り直した後 |
|---|---|---|---|---|
| 角の数（100 人） | 1228 | 1221 | 1192 | 1168 |
| 重い角（危険が届かない、何の知らせか分からない） | 89 | 72 | 69 | 46 |
| たたんだ通知の分かった度合い（0–3） | 1.44 | 1.39 | 1.36 | 1.80 |

直した角（挙げた人の数）:
- 題が切れて「気をつけて」が見えない: 72 → 0。直したあとに出た「題が切れてレベルの数字が見えない」: 74 → 0
- 位置が古い: 99 → 0（2 つを直した後は 2、作り直した後は 8。8 のほとんどは位置ではなく、携帯の時計「8:46」と文の「20:45」の書き方のちがいに迷った角）
- 語が行の途中で割れる（みず／が、初／台）: 43 → 0
- 「止める」ボタン: 97 → 94 → 81 → 87。音や鳴る知らせを止めるボタンと取りちがえた角は 45 → 35 → 5、重い角は 8 → 3 → 0。ボタンは「見守りを止める」にし、押すと止めてよいかを聞きます（この確かめの画面は 4 枚の写しに入っていません）。残りの角の多くは「大きいボタンで、読めないまま押しそう」です。

作り直し（[調べもの](#知らせの作り)にそって、題・たたんだ 1 行・本文を作り直した。2 つを直した後 → 作り直した後、挙げた人の数）:
- 🌊 を津波と読む: 33 → 0
- 試しの行「ほかは本物」が分からない: 99 → 0
- 試し／TEST を練習・訓練と読む: 32 → 6
- たたんだ通知（題と 1 行）が漢字や言葉で読めない: 64 → 42
- 何をすればよいか書いてない: 98 → 86。「〜に警戒してください」だけでは、何をすればよいか分からないという角が残ります。
- 新しく出た角: 「本物は「道路」の行」という言い方が分かりにくい（多くは小さい角）。時刻を携帯の時計とちがう書き方（20:45）で出すので、いつの知らせか迷う。

### AI はすべての角を取ろうとし、人が選ぶ

作りものの人は、見えた不満を全部、角として挙げます（1 人あたり約 12）。AI は、それを全部取ろうとします。
でも、全部を取ると、サークルの決まりとぶつかる角もあります。たとえば「お年寄りは逃げて、と書いてほしい」は、サークルが書かないと決めた「どう動くか」です。
そこで、どれを直し、どれをわざと残し、どれをしないかは、人が角を読んで決めました。最後に決めるのは人です（human-in-the-loop）。角を数え尽くす AI と、選ぶ人と、どっちも要ります。

| 決め | 角の中身 | 作り直した後の角の数 |
|---|---|---|
| 直した | 題が切れる、語が割れる、位置が古い、ページの名前が二度出る | 9（多くは時刻の書き方） |
| 直した | レベルの数字、「止める」ボタン | 88（多くは新しい「見守りを止める」への角） |
| 直した | 試しの行。作りものの警報を本物と取りちがえないための行なので消さず、試しの印を 1 か所にし、「ほかは本物」をやめて本物の行を名指しした | 145（多くは「本物は「道路」の行」の言い方への小さい角） |
| 直した | 同じ文が漢字・ひらがな・英語で並ぶ。同じ警報を 1 回ずつにし、ひらがな・英語の行はその言葉の人だけが読む短い行にした | 56 |
| まだ | ほかの言葉で読みたい。画面には公式の事実だけを出すので、英語も気象庁の公式の英語だけ | 122 |
| 一部直した | 道の行（冠水想定・アンダー）が分からない。やさしい日本語の行は「ちかくの みちが みずに つかる」と言いかえた | 136 |
| 一部直した | どう動くかを書いてほしい。気象庁の形で「〜に警戒してください」と、何に気をつけるかを具体に書く。逃げる・避難の指図は書かない | 95 |
| 振り分けていない | 人ごとにちがう角、小さい角 | 517 |

- 角の振り分けは、言葉で当てた目安です。一つの角は、上の行から順に、最初に当たった一つの行にだけ数えます。
- 1168 のうち 517 は、まだ振り分けていません。
- 作りものの人の答えで、本物の人の声ではありません。同じ写しでも、回ごとに答えは少しゆれます。
- 決めた理由と決めた人、ほかの表は [persona/runs/look-after3/tally.md](persona/runs/look-after3/tally.md) にあります。

## 読んでいるもの

- 気象庁: 警報・注意報、指定河川洪水予報、キキクル（土砂災害・浸水害）、降水ナウキャスト、アメダス
- ハザードマップポータルサイト: 洪水・内水・高潮・津波の浸水想定区域、土砂災害警戒区域など
- 国土地理院: 自然災害伝承碑
- 国土交通省 道路防災情報webマップ: 道路冠水想定箇所（各地方整備局・北海道開発局の KML。沖縄県の分は無い）
- 秋田県 ツキノワグマ等情報マップシステム「クマダス」データ: クマ・イノシシ・シカの出没の記録（画面には地点から 3km・1 年の分。ツキノワグマが 1km 以内・60 日以内にあると通知のきっかけにする。県のデータはまとめて公開されるので、30 日では届く前に過ぎてしまう。イノシシ・シカは画面に出すだけ。ほかの都道府県の分は、機械で読める形の公開データが見つかっていないので無い）

## 出典

- 出典：気象庁ホームページ。キキクルと降水ナウキャストは、地図画像の画素の色を読み取って文字にしています。
- ハザードマップポータルサイト（国土交通省・国土地理院）。データは国土交通省・都道府県・市町村等。地図画像の画素の色を読み取って文字にしています。
- 出典：国土地理院 自然災害伝承碑。
- 出典：国土交通省 各地方整備局・北海道開発局ホームページ（道路防災情報webマップの道路冠水想定箇所 KML）を加工して作成。加工は地点からの距離の計算と並べ替えです。各局とも公共データ利用規約（PDL1.0）。使った KML の URL は結果の `road_flood.sources` と画面に出ます。
- 出典：秋田県「ツキノワグマ等情報マップシステム『クマダス』データ」（秋田県オープンデータカタログ、CC BY 4.0）を加工して作成。加工は地点からの距離の計算と、新しい順の並べ替えと数えることです。
